PDF statements, QFX / OFX downloads and CSV exports, all in one go — each file goes its own way.

How this works

PDF statements are read by the AI in the background. Unless you skip it, each one then waits for you to open it and confirm its money in and money out (Waiting for you, below); once it completes, the PDF is deleted. A PDF needs an account: the one whose last 4 digits are in the file name, else the one you used last time, else pick it.

QFX / OFX / QBO downloads (Quicken or Money format) are read at once, with no AI and no confirmation: their rows, account number and closing balance are in the file. “Match by account number” sends each account in the file to yours with the same last 4 digits; when nothing matches you're asked which account it is, in the file's row. Overlapping downloads only add the new rows.

CSV files need the columns Date, Description and Amount — or Debit and Credit instead of Amount (on a credit card Debit is a purchase and Credit a payment; on checking it's the other way round). Category is optional (blank rows are categorized like a statement's), and Account lets one file fill several accounts (names must match yours; a row without one uses the account picked for the file). A bank's own lines above the header are skipped by themselves; under Header and data rows you can choose them yourself. With several date columns, the transaction date is used, or you're asked. A file missing a required column imports nothing. Export your transactions to see the format. After an import you can remember its layout for the account, and it's used by itself next time.

Signs: checking and savings — negative is money out, positive is money in. Credit card — positive is a purchase, negative a payment.

A file whose type isn't its account's preferred upload method (set on Accounts) gets a small “not this account's usual type” mark — a reminder in case the wrong account is picked, never a block. Rows already in the app are skipped as duplicates and listed on Review for Insert anyway.
