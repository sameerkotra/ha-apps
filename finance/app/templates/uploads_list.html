New account details

Add a transaction by hand

Checking/savings: negative = money out, positive = money in. Credit card: positive = a purchase (charged to the card), negative = a payment (paid toward it) — see the Transfers page if this is actually one side of a transfer between your own accounts.

Import a CSV

Required columns: Date, Description, Amount — or Debit and Credit instead of Amount, if that's the shape your export uses (whichever one has a value on a row supplies the amount; on a credit card, Debit is a purchase and Credit is a payment, the opposite of a checking account where Debit is money out and Credit is money in). Category is optional — left blank, each row gets categorized the same way an uploaded statement's transactions do. Account is only required as a column if you leave the picker above on “Use Account column in CSV” — pick a specific account instead and every row without its own Account cell filled in uses that account, same as the PDF upload above. A row that does have its own Account value still needs it to match one of your account names exactly (case-insensitive), letting one file mix accounts per row even with a default picked. The whole file is rejected up front if a required column is missing — nothing is imported instead of the rows around a bad one being silently skipped. If a file has more than one date-like column (a credit card's “Trans. Date” and “Post Date,” say), the one that looks like the transaction date is used automatically; if it's not clear which one that is, you'll be asked to pick before anything is imported. Export your current transactions to see the format. The uploaded file itself is deleted right after import, same as a statement's PDF once it's no longer needed. If the account you pick above has a preferred upload method (set on the Accounts page) that isn't CSV, you'll see a warning before the import runs — it's just a check in case the wrong account got selected, and you can dismiss it and import anyway.
